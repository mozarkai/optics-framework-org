# Optics skills

> Each skill is the procedure for one whole task with Optics. Fetch the one that fits your task and follow it. You do not have to install it.

- [data-driven-tests](https://optics-framework.org/.well-known/agent-skills/data-driven-tests/SKILL.md): Run one Optics flow for each value of a list with Run Loop, read test data from a CSV file, a JSON file or an environment variable with Read Data, and keep a value from one step for a later step. Use when a person asks for a parametrized or data-driven test, or when a suite repeats the same steps with different values.
- [detect-error-screens](https://optics-framework.org/.well-known/agent-skills/detect-error-screens/SKILL.md): Make an Optics run fail when the app ends on a crash dialog, a "Session expired" message or another error text, with an error_definitions.csv file. Use when a test passes while the app shows an error, or when a person asks to catch crashes and error screens in CI.
- [enable-self-heal](https://optics-framework.org/.well-known/agent-skills/enable-self-heal/SKILL.md): Turn on Optics AI self-heal, so that a model reads the screen and completes a step when no locator finds its element, then read the heal report and correct the element. Use for a long or scheduled run that must continue after small UI changes, or when a person asks for self-healing tests.
- [explore-an-app](https://optics-framework.org/.well-known/agent-skills/explore-an-app/SKILL.md): Explore an app or a website with the Optics MCP tools, map its screens and flows, and write a test plan before any test is written. Use when a person asks to explore an app, find what to test, or build a suite for an app that has no tests.
- [export-to-code](https://optics-framework.org/.well-known/agent-skills/export-to-code/SKILL.md): Turn an Optics CSV or YAML suite into a pytest or Robot Framework file with `optics generate`, or write a test with the Optics Python class. Use when a suite needs logic that the files do not have, or when a team runs its tests through pytest or Robot Framework.
- [find-by-text-and-image](https://optics-framework.org/.well-known/agent-skills/find-by-text-and-image/SKILL.md): Turn on OCR and image matching in Optics to find text and icons that are not in the UI tree, such as text in an image, a canvas, a game, a video player or a camera frame. Use when an element shows on the screen but a step does not find it, or when a person asks for visual or OCR locators.
- [fix-a-failed-run](https://optics-framework.org/.well-known/agent-skills/fix-a-failed-run/SKILL.md): Find why an Optics run failed from its exit code, JUnit report, screenshots and failed_steps_elements.json, correct the cause, and run again until it passes. Use when `optics execute` or `optics dry_run` fails, a test is flaky, or a person asks why an Optics test failed.
- [handle-popups](https://optics-framework.org/.well-known/agent-skills/handle-popups/SKILL.md): Write Optics popup rules that close offers, rating requests, update notices and permission prompts on Android and iOS, and stop the run on a popup that must not be pressed. Use when a popup covers an element, when a step fails with E0206, E0407 or E0408, or when a system alert blocks a test.
- [harden-locators](https://optics-framework.org/.well-known/agent-skills/harden-locators/SKILL.md): Make the elements of an Optics suite continue to match after the app changes, with ordered fallback values, exact locators and waits in place of sleeps. Use when a test is flaky, when a redesign broke a suite, or before a suite goes into CI.
- [migrate-to-optics](https://optics-framework.org/.well-known/agent-skills/migrate-to-optics/SKILL.md): Migrate an Appium, Selenium, Playwright, Cypress, Maestro, Detox, Espresso or XCUITest suite to Optics (optics-framework) one test at a time, with each assertion kept and each migrated test run on the app. Use when a person asks to move, port or convert UI tests to Optics.
- [optics-framework](https://optics-framework.org/.well-known/agent-skills/optics-framework/SKILL.md): Drive Android, iOS, smart TV, desktop app and browser sessions with the Optics (optics-framework) MCP server, and write or fix Optics CSV/YAML test suites (test_cases, modules, elements, error_definitions). Use when automating or testing a real app UI with Optics, or when an Optics keyword name, parameter or default is uncertain.
- [reproduce-a-bug](https://optics-framework.org/.well-known/agent-skills/reproduce-a-bug/SKILL.md): Reproduce a reported bug of an app or a website with the Optics MCP tools, collect the evidence, and write an Optics test case that fails while the bug exists. Use when a person gives a bug report, a ticket or a "this is broken" message and asks to reproduce, confirm or pin it.
- [run-in-ci](https://optics-framework.org/.well-known/agent-skills/run-in-ci/SKILL.md): Add an Optics suite to GitHub Actions, GitLab CI or another CI system, with the engines installed, a headless browser or an emulator, the JUnit report published and the output kept. Use when a person asks to run Optics tests on every push, pull request or build.
- [set-up-android](https://optics-framework.org/.well-known/agent-skills/set-up-android/SKILL.md): Get an Android phone, emulator or Android TV ready for Optics with Appium, UiAutomator2 and adb, then start a session on the app. Use when an Appium session on Android does not start, when `optics doctor` shows a mobile problem, or when a person asks to test an Android app.
- [set-up-bluetooth](https://optics-framework.org/.well-known/agent-skills/set-up-bluetooth/SKILL.md): Get a phone, tablet or computer ready for Optics with nothing installed on it, through an airhand Bluetooth dongle and a camera or a USB screen. Use when a `ble` session does not start, when an app blocks USB debugging or screenshots, or when a person asks to test a production device.
- [set-up-desktop](https://optics-framework.org/.well-known/agent-skills/set-up-desktop/SKILL.md): Get a macOS, Windows or Linux computer ready for Optics to drive a desktop app through Appium and appium-xa11y-driver, then start a session on the app. Use when a desktop session does not start, when macOS permissions are missing, or when a person asks to test or automate a desktop app.
- [set-up-ios](https://optics-framework.org/.well-known/agent-skills/set-up-ios/SKILL.md): Get an iOS simulator or an iPhone ready for Optics with Appium and the XCUITest driver, then start a session on the app. Use when an Appium session on iOS does not start, when a person asks to test an iOS app, or when a system alert blocks an iOS test.
- [set-up-tv](https://optics-framework.org/.well-known/agent-skills/set-up-tv/SKILL.md): Get a Samsung Tizen TV, an LG webOS TV or an Android TV ready for Optics through Appium, then start a session on the TV app and move with remote keys. Use when a TV session does not start, or when a person asks to test a smart TV app.
- [sign-in-and-secrets](https://optics-framework.org/.well-known/agent-skills/sign-in-and-secrets/SKILL.md): Sign in to an app or a website in an Optics session or suite, and keep passwords, tokens and one-time codes out of files, logs and reports. Use when a flow needs a sign-in, when a suite types a credential, or when a secret shows in a log or a commit.
- [test-mobile-web](https://optics-framework.org/.well-known/agent-skills/test-mobile-web/SKILL.md): Test a website in Chrome on Android or Safari on iOS, or a web page inside a mobile app, with one Optics Appium session that reads native and web elements together. Use when a person asks to test a mobile website, a WebView or a flow that goes from an app to a browser.
- [write-a-suite](https://optics-framework.org/.well-known/agent-skills/write-a-suite/SKILL.md): Turn the steps of an Optics MCP session into a test suite that `optics execute` runs and that a person can read and review. Use when a person asks to save, record or write a flow as an Optics suite, or after a session ended and its steps must become a test.

For a keyword, a setting or an error code, read the docs index: https://optics-framework.org/docs/llms.txt
