Handle popups

Write rules that close the popups that block a step, and stop the run on popups you did not plan for.

Intermediate, about 10 min

View as Markdown

Apps show popups at times you cannot plan: an offer, a rating request, an update notice, a session timeout or a permission prompt. When a popup covers the element that a step needs, the step fails. Popup rules tell Optics what each known popup looks like and what to do about it.

When a step cannot find its element, Optics does this:

  1. It reads the screen and tries your rules in list order. The first rule that matches wins.
  2. It does the rule's action, such as a tap on Not now, and waits up to 5 seconds for the popup to go.
  3. It tries the step again.

If no rule matches but the screen shows a dialog, the step fails with E0206 and Optics saves a screenshot and the page source. Optics never guesses which button to press.

Nothing changes until you write a rule. A step that finds its element reads nothing more and tries no rule. Rules run before AI self-heal, so a known popup costs no LLM call.

Appium only

Popup rules work on Android and iOS apps through Appium. Playwright, Selenium and the other drivers see no popups. On those drivers, use Detect And Press for a popup that shows only sometimes.

Try it in your browser

The popups playground runs the real popup guard against eleven popups on a demo app. Turn each popup and each rule on or off, then watch what Optics does.

Rule fields#

FieldDefaultWhat it does
nameRequiredThe name of the rule. Each name must be unique.
detectRequiredWhat the popup looks like. See Detect a popup.
action{"type": "none"}What to do about the popup. See Actions.
thenretry_stepWhat happens after the action: retry_step, fail_step or stop_run. See After the action.
checkon_failureWhen to check: on_failure, after a step does not find its element, or before_every_step. See Check before every step.
sensitivefalsetrue presses nothing, saves the evidence and ends the run. See Sensitive popups.
max_per_step2How many times the rule can act in one step.
max_per_run5How many times the rule can act in one run.

Detect a popup#

detect takes one or more keys. Every key that you give must match the screen.

KeyMatches when
text_containsAny one of the strings is part of the text on the screen. Case does not matter.
resource_idAn element has exactly this resource id, such as com.birch.shop:id/promo_close.
xpathThe XPath finds at least one element in the page source.

text_contains searches all the text on the screen, not only the popup. Use text that only the popup shows, or add a resource_id or xpath key, so the rule does not match a normal screen.

Actions#

typetargetWhat it does
tapRequiredTaps the element target names: text, a resource id or an XPath. Optics uses the position from the page source. If the target is not there, it searches the screen as Press Element does.
backNonePresses back, as Go Back does.
alertRequirediOS only. Presses the button with this label on a system alert, such as Allow. See iOS.
moduleRequiredRuns the module with this name from your suite. Use it for a popup that needs more than one tap.
noneNoneDoes nothing. Use it with then: fail_step or then: stop_run to stop and keep the evidence.

Run a module#

A module action runs a module from your modules file, in the same session. Any keyword works in it:

  • Other popup rules stay on while the module runs. The rule that started the module does not act on its own popup until the module ends.
  • When the module fails, or ends with the popup still on the screen, the step fails with E0408.
  • When the session has no module with that name, the step fails with E0601.

After the action#

thenWhat happens
retry_stepOptics tries the step again. The rule needs an action other than none.
fail_stepThe step fails with E0408. The run continues with the next test case.
stop_runThe step fails with E0408, and the test cases that have not started do not run. They show as NOT_RUN.

When the popup is still on the screen 5 seconds after the action, the step fails with E0408, whatever then says.

Sensitive popups#

Set sensitive: true for a popup that you must never press, such as a payment or account deletion prompt. Optics ignores action and then, presses nothing, saves a screenshot and the page source, and stops the run with E0408:

Check before every step#

Some popups do not block the element. A session timeout dialog can leave the screen below it visible. Set check: before_every_step to try the rule before each step that finds an element. See Steps that check for popups for the keywords:

When a rule closes a popup and the step tries again, the before-every-step rules run again first.

Each such step reads the page source once more, so use this only for popups that need it.

Limits#

max_per_step and max_per_run stop a popup that comes back again and again. When a rule reaches a limit, the step fails with E0407 and the run continues:

Popups with no rule#

When a step does not find its element, no rule matches and the screen shows a dialog, the step fails with E0206:

Copy text from the message into a new rule. The screenshot and the page source in the output folder show the popup.

  • Optics finds dialogs, alerts, bottom sheets and system prompts. A popup that the app draws as a normal view is not found as a dialog, so the step fails with E0201 as before. Write a rule for it.
  • Optics looks for unknown popups only when the project has at least one rule.

Steps that check for popups#

The rules run for keywords that find an element:

  • Press Element, Enter Text, Enter Number, Clear Element Text, Get Text, Swipe From Element and Scroll From Element.
  • Assert Presence, Assert Visibility, Assert Text, Is Element, Validate Element and Validate Screen. When the element is not found and a rule closes a popup, the assertion looks again with its full timeout.

A popup that stops the step, such as a popup with no rule (E0206), fails Validate Screen too. Is Element with invisible passes only when no popup is on screen.

Other keywords do not check for popups:

  • Detect And Press, Swipe Until Element Appears and Scroll Until Element Appears.
  • Steps that use coordinates or the whole screen, such as Press By Coordinates, Swipe and Scroll.

Evidence and events#

Each time a rule acts or a popup stops a step, Optics saves files to the output folder:

FileWhen
popup_<run>_<n>_before.pngBefore the action, and for a popup with no rule.
popup_<run>_<n>_after.pngAfter the action.
popup_<run>_<n>_source.xmlWhen the popup stops the step or the run.

Optics saves these files only when save_captures is on. The screenshots also need a screenshot source, such as appium_screenshot. optics serve turns captures off, so it saves no files.

With --output jsonl, each popup is an event with "entity_type": "popup". Its args hold the details:

  • verdict is handled, stopped, limit or unknown.
  • popup_kind is system_alert for a prompt of the operating system, and in_app for a popup of the app.
  • The event also names the keyword, the element, the test case and the module.

Where to put rules#

Optics reads rules from these places. A rule replaces an earlier rule with the same name.

  • popup_rules in config.yaml, as a list in the same format.
  • Every file named popup_rules.json in the project, in path order. optics execute, optics dry_run, optics live and optics generate read them. See Project files.
  • Over HTTP, popup_rules when you start a session, or PUT /v1/sessions/{id}/popup_rules later. See Popups over HTTP.
  • In Python and Robot Framework, add_popup_rules (Add Popup Rules). Read the results with get_popup_events and get_popup_summary.

optics generate copies the rules into the generated code. When a rule runs a module, the generated code also gets every module and element of the suite.

Permission prompts#

On Android, set permissions in config.yaml to grant or deny app permissions before the app opens, so the prompt never shows. See Android. On iOS, answer system alerts with a capability or an alert action. See iOS.
