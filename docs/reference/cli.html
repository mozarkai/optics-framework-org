CLI

Look up every `optics` command, its flags, what it writes and the exit codes it returns.

View as Markdown

The optics command creates projects, checks your setup, runs tests and starts the integration servers. This page covers Optics 1.10.5.

Commands are grouped by when you use them: getting started, running tests, integrating with other tools, and everything else. Run optics <command> --help to see the same flags in your terminal.

Global behavior#

FlagWhat it does
--versionPrints Optics Framework 1.10.5 and exits with code 0.
--help, -hLists the commands: list, configure, config, doctor, quickstart, dry_run, init, execute, live, generate, setup, serve, mcp, completion.

There's no optics version command. Use optics --version.

When you run optics with no command for the first time, it prints a welcome panel that points to optics quickstart, optics doctor and optics --help. After that, it prints a one-line reminder. Optics remembers the first run in a small marker file under ~/.optics (or $OPTICS_HOME).

If Optics can't load one of its own dependencies, every command stops with a red "Cannot start" panel. The panel shows the underlying error and the reinstall command for your environment, for example pipx reinstall optics-framework or pip install --force-reinstall optics-framework.

When a command fails unexpectedly, Optics prints Unexpected error (<type>): <message> and suggests running optics doctor. See Exit codes.

optics quickstart#

Walks you through creating your first project, installing an engine, writing config.yaml and running a test.

There are no flags. The command asks these questions in order:

  1. What do you want to automate? mobile or web.
  2. Install the engine now? Appium for mobile; Playwright and Selenium for web. If you decline, it prints the optics setup --install command to run later.
  3. Start from a sample? The contact sample for mobile, the playwright sample for web. Decline to pick an empty project or another sample.
  4. Project name (default my-optics-project) and where it should live (default: the current folder). If the folder exists, it asks for another name.
  5. Config questions. If the sample ships its own config.yaml, you choose whether to overwrite it. The default is yes for mobile and no for web.
  6. It runs optics doctor on the new project and shows the report.
  7. If the report shows no blocking problems, it offers to run your first test with optics execute.

Quickstart never runs optics dry_run. It writes the same files as optics init and optics configure.

Tip

The web path with the playwright sample needs no device or server. It's the fastest way to see a passing run.

optics init#

Creates a new project folder, either blank or copied from a sample.

ArgumentDefaultWhat it does
nameAsks for itThe project name. The project goes in <path>/<name>.
--pathCurrent folderThe parent folder. Missing folders are created.
--templateAsks in a terminal; blank otherwiseCopies a sample project. One of calendar, clock, contact, gmail_web, playwright, youtube.
--forceOffDeletes an existing folder with the same name first. Without it, an existing folder is an error and nothing is created.
--git-initOffRuns git init in the new project. Skipped quietly if Git isn't installed.
--nameDeprecated. Pass the name as the first argument instead.

In a terminal without --template, Optics shows a numbered list: (Blank project), Contacts, Clock, Calendar, YouTube, Gmail Web and Playwright Web. Press Enter on a blank answer to cancel.

A blank project contains:

SampleTargetEngines it uses
contactGoogle Contacts on an Android emulatorAppium, EasyOCR. Includes an error definitions file.
clockAndroid Clock appAppium, Pytesseract, image templates. Shows Run Loop.
calendarAndroid Calendar appAppium, EasyOCR. Shows Invoke API and Date Evaluate.
youtubeYouTube on AndroidAppium, EasyOCR, image templates. Shows Condition.
gmail_webGmail in ChromeSelenium, EasyOCR.
playwrighthttps://example.comPlaywright. Needs no device or server.

Exit code 3 if the project already exists, the template name is unknown, or the name is empty.

optics configure#

Writes a project's config.yaml by asking a few questions, or opens a full editor.

ArgumentDefaultWhat it does
folderCurrent folderThe project folder. It's created if it doesn't exist.
--editOffOpens a full-screen editor over every config.yaml setting instead of the questions.

Guided mode asks what you're automating (android, ios, web-playwright or web-selenium), then the details for that platform:

PlatformQuestions (defaults)
androidDevice name (emulator-5554), platform name (Android), app package (com.example.app), main activity (com.example.app.MainActivity), Appium server URL (http://127.0.0.1:4723)
iosDevice or simulator name (iPhone 15), platform name (iOS), bundle identifier (com.example.app), Appium server URL
web-seleniumSelenium server URL (http://127.0.0.1:4444/wd/hub)
web-playwrightBrowser (chromium), headless (no)

Every platform then asks whether to find elements by on-screen text with EasyOCR, and the log level. If config.yaml already exists, Optics asks before overwriting it.

Warning

The web-selenium answer writes capabilities: {}, which Selenium can't start with. Add browserName: chrome (or firefox) under capabilities before you run. See config.yaml.

Editor mode (--edit) uses these keys: ↑/↓ to move, Space to edit or toggle, S to save, Q to quit. Saving rewrites the whole file and removes your comments. Editing an engine list replaces it with enabled: true entries and drops their url and capabilities, so we recommend guided mode or a text editor for engine settings.

optics doctor#

Checks your Python, installed engines, device tools and project config, and tells you what to fix.

ArgumentDefaultWhat it does
folderNoneThe project to validate. Without it, doctor checks your environment only and doesn't validate any config.yaml.
--checkOffExits with code 1 if any row is ❌. Use it in CI.

Doctor prints one row per check: ✅ ok, ⚠️ warning (optional or not yet needed) or ❌ failure. Each problem row has a → hint with the fix.

SectionWhat it checks
CorePython version (Optics needs 3.12 or later), the installed Optics version, and whether this environment allows engine installs.
EnginesWhether each engine package is installed: Appium, BLE, Selenium, Playwright, EasyOCR, Pytesseract, Google Vision, Gemini, OpenAI, Anthropic.
Mobileadb on your PATH, connected Android devices, and whether the Appium server answers (the project's URL, or 127.0.0.1:4723).
WebThe Playwright Chromium browser, and chromedriver or geckodriver on your PATH.
ProjectWith a folder: config.yaml parses, exactly one driver is enabled, the driver's element sources are enabled, and the driver has the settings it needs (for example url, platformName, and bundleId on iOS).

Only project rows can be ❌. Environment rows are ✅ or ⚠️. Without --check, doctor always exits with 0.

Doctor doesn't check Selenium capabilities, and it doesn't create any output folders.

optics setup#

Installs the optional engines Optics needs for your platform: drivers, OCR and LLM.

ArgumentWhat it does
(none)Opens a full-screen picker with checkboxes for each engine.
--listPrints every engine and bundle you can install. Wins if you also pass --install.
--installInstalls the named engines or bundles.

Names are case-insensitive. You can use an engine name (appium, ble, selenium, playwright, easyocr, pytesseract, google-vision, gemini, openai, anthropic), a display name (Gemini, Google Vision) or a bundle (mobile, web, vision, llm, all). Pin a version with a standard specifier such as appium==5.0.0 or "easyocr>=1.7,<2.0".

optics setup installs into the same Python environment as Optics. If you install Playwright, it also downloads the Chromium browser. Some environments refuse installs, for example Conda, pipx and uv tool. See Engines and extras.

The MCP server isn't an engine here. Install it with pip install "optics-framework[mcp]".

Exit code 1 if a name is unknown, a version specifier is malformed (appium=5.0.0), or the install fails.

optics dry_run#

Checks a project for mistakes without running any step on a device.

ArgumentDefaultWhat it does
folderRequiredThe project folder. It must exist.
--runnertest_runnerThe runner. Leave the default.
--use-printer / --no-use-printerPrinter onShows or hides the live result tree.

A dry run checks that:

  • Each test step names a module (or a keyword).
  • Each module step names a real keyword. A typo gets a suggestion: Did you mean 'Press Element'?
  • Each whole-cell ${name} is defined in your elements files.

It doesn't run any keyword or touch the device. It does load the engines in config.yaml, so the engine extras must be installed, a driver must be enabled, and its settings must be valid (for example non-empty Appium capabilities).

Common mistake

Variables that a step creates while running, such as the target of Evaluate or Read Data, don't exist yet during a dry run. Declare them in elements.csv with a placeholder value, for example order_total,placeholder, so the dry run passes.

The output and exit codes are the same as optics execute. Dry runs write junit_output.xml to execution_output/ but no screenshots.

optics execute#

Runs every test case in a project on the real device, browser or app, and records the results.

ArgumentDefaultWhat it does
folderRequiredThe project folder. It must exist.
--runnertest_runnerThe runner. We recommend the default. pytest is also accepted, but it needs the pytest-cov package installed.
--use-printer / --no-use-printerPrinter onShows or hides the live result tree. Turn it off for plain CI logs.

There are no flags to pick tests or tags. To run a subset, use include or exclude in config.yaml.

What happens, in order:

  1. Optics walks the whole folder and finds your files by their content (see Project files). It stops if there's no test cases file or no modules file.
  2. It loads the config and stops if no driver is enabled.
  3. Preflight. It checks that the first enabled driver can be reached. For Appium it connects to the server URL and, on Android, checks that adb finds a device. For Selenium it connects to the server URL. Playwright is skipped. If the check fails, Optics shows a "Cannot start" panel with the command that fixes it. Set OPTICS_SKIP_PREFLIGHT=1 to skip this check.
  4. It runs Suite Setup, then each test case, then Suite Teardown. A failing test case doesn't stop the others.
  5. It saves a final screenshot and page source, and runs error detection if the project has an error definitions file.

The printer shows a live tree, then a summary:

When a step fails, a "Failure details" box names the test, the step and the reason:

Results go to execution_output/ in the project: junit_output.xml, screenshots, and logs if you turn them on. See Project files.

Exit codeWhen
0Every test case passed.
1Any test case failed, required files are missing, no driver is enabled, the preflight failed, or the folder doesn't exist.

On-screen errors found by error detection appear in junit_output.xml as a failing test case, but they don't change the exit code.

optics live#

Opens an interactive session where you type keywords, see each result straight away, and save what worked as a test.

ArgumentDefaultWhat it does
folderCurrent folderThe project folder. It must contain a config.yaml.

The config must enable exactly one driver and at least one element source. Without a config, optics live stops with an error; there are no built-in defaults. Live runs launch_app as soon as it starts.

Type a keyword with its parameters, for example press_element ${sign_in} or enter_text ${email_field} "ana@birch.example". Each result appears as two lines:

CommandWhat it does
/save <test_case> <module>Saves the steps you've run since the last save as a module and a test case in CSV. Names can't contain spaces.
/device [id]Lists connected Android and iOS devices, or switches to one. Appium only.
/elementsShows the named elements in the project.
/screenshotSaves a screenshot to screenshots/ in the project.
/helpShows help.
/quit, /exitQuits. Warns once if you have unsaved steps.
KeyWhat it does
Tab / Shift+TabCompletes keyword names.
${Suggests element names.
Ctrl+KOpens the keyword browser.
Ctrl+NSwitches to plain-English mode. Needs an enabled llm_models entry.
Ctrl+XStops a running plain-English instruction.
Ctrl+CQuits.

Live writes its log to logs/optics_live_<time>.log and its screenshots to screenshots/session_<time>/ in the project. See Record a test for a full walkthrough.

optics serve#

Starts the HTTP API so any language or tool can drive a device through Optics.

FlagDefaultWhat it does
--host127.0.0.1The address to listen on.
--port8000The port to listen on.
--workers1Server processes. Keep it at 1: sessions live in memory and aren't shared between processes.

Warning

The API has no authentication and accepts requests from any web origin. Keep the default 127.0.0.1 unless you're on a trusted network.

The server doesn't read config.yaml. Each session gets its settings from the request. Interactive API docs are at http://127.0.0.1:8000/docs. See HTTP API.

optics mcp#

Starts the MCP server, which lets an AI agent such as Claude or Cursor drive a device with Optics keywords.

FlagDefaultWhat it does
--transportstdiostdio for agents that start the server themselves; http to serve at http://<host>:<port>/mcp.
--host127.0.0.1The address to listen on. http only.
--port8090The port to listen on. http only.

It needs the mcp extra: pip install "optics-framework[mcp]". The all bundle doesn't include it. Without the extra, the command exits with code 1 and prints the install command. See MCP server.

optics generate#

Turns a CSV or YAML project into pytest or Robot Framework code.

ArgumentDefaultWhat it does
folderRequiredThe project folder.
--frameworkpytestpytest or robot.
--outputtest_generated.py or test_generated.robotA file name, not a path. The file always goes in <folder>/generated/Tests/.

It writes:

  • generated/Tests/<file>: the generated tests.
  • generated/requirements.txt: the packages the generated code needs.
  • generated/Tests/input_templates/: a copy of input_templates/ if that folder sits at the project root.

Generate has stricter needs than optics execute:

  • The config file must be named exactly config.yaml.
  • The project needs an elements file. Only the Element_ID column is used; fallback columns are ignored.
  • Flow-control keywords (Run Loop, Condition, Evaluate and the rest) and a few others are skipped without a warning.
  • Suite Setup and Suite Teardown become ordinary tests.

Exit code 3 if a required file is missing or two files define the same name. See Generate code.

optics list#

Prints every keyword you can use, grouped by category.

Names are printed in snake_case. In a module, write them in Title Case with spaces: press_element becomes Press Element. Matching ignores case and spaces, so both forms work.

For parameters and examples, see Keywords.

optics completion#

Turns on tab completion for optics in bash or zsh.

It writes ~/.optics/optics_completion.sh and ~/.optics/optics_completion.zsh, then offers to add a source line to ~/.zshrc or ~/.bashrc, based on $SHELL. Other shells aren't supported. Restart your shell, or run source ~/.zshrc, to use it. To remove it, delete the line from your shell profile.

optics config#

Deprecated. Use optics configure.

It prints a deprecation notice, then runs guided optics configure on the current folder. There's no global config file any more: every setting lives in the project's config.yaml.

Exit codes#

CodeMeaning
0Success. For optics execute and optics dry_run, every test case passed.
1A test case failed, a check failed (optics doctor --check, preflight), a required file or setting is missing, or an unexpected error occurred.
2The command line was invalid, for example an unknown flag or a missing argument.
3The input was invalid, for example a project that already exists, an unknown template, or files optics generate needs. The message starts with Error:.
130You pressed Ctrl+C. Optics prints Operation cancelled by user.

Environment variables#

None of these override config.yaml. Settings for optics execute, dry_run and live come only from the project's config.yaml.

VariableUsed byWhat it does
OPTICS_SKIP_PREFLIGHTexecuteSet to 1 or true to skip the server and device check before a run.
OPTICS_HOMEopticsFolder for the first-run marker. Default ~/.optics.
OPTICS_AI_SELF_HEALserve, mcpSet to 1, true, yes or on to turn on AI self-heal for every session by default.
OPTICS_LLM_PROVIDERserve, mcpThe LLM engine for self-heal: gemini (default), openai or anthropic.
OPTICS_LLM_MODELserve, mcpThe model for self-heal. Gemini defaults to gemini-2.5-flash; openai and anthropic need one.
OPTICS_MCP_ALLOW_COORDINATE_TAPSmcpSet to 1, true, yes or on to expose the press_by_coordinates and press_by_percentage tools.
OPTICS_EVENT_DRAIN_TIMEOUT_Sexecute, serveSeconds to wait for events to flush at the end of a run. Default 2.0. Raise it if junit_output.xml is cut short on long runs.
PLAYWRIGHT_BROWSERS_PATHdoctor, PlaywrightWhere Playwright browsers are installed.
GEMINI_API_KEY or GOOGLE_API_KEYGeminiAPI key for the Gemini Developer API.
GOOGLE_GENAI_USE_VERTEXAI, GOOGLE_CLOUD_PROJECT, GOOGLE_CLOUD_LOCATION, GOOGLE_APPLICATION_CREDENTIALSGemini, Google VisionUse Vertex AI and Google Cloud credentials instead of an API key.
OPENAI_API_KEYopenai engineAPI key for OpenAI. Set api_key_env in config.yaml to read another variable.
OPENAI_BASE_URLopenai engineThe server to call when the entry has no url, such as OpenRouter or a local Ollama.
ANTHROPIC_API_KEYanthropic engineAPI key for the Claude API.

Install scripts#

The install scripts put Optics in its own virtual environment under ~/.optics and add the optics command to your PATH. They don't change your system Python. Python 3.12 or later is the one prerequisite.

Pass options after sh -s --:

OptionEnvironment variableWhat it does
--version X.Y.ZOPTICS_VERSIONInstalls a specific release.
--extra a,bAlso installs engine extras, for example appium,llm.
--dir PATHOPTICS_INSTALL_DIRInstalls somewhere other than ~/.optics.
--no-modify-pathOPTICS_NO_MODIFY_PATHLeaves your shell profile alone.
--dry-runPrints what would happen and changes nothing.
--uninstallRemoves the install folder. Remove the Optics block from your shell profile yourself.
--helpShows the options.

On Windows under Git Bash, MSYS2 or Cygwin, the script stops and points you to the PowerShell installer. Inside WSL, use this script.

Piping into iex can't pass parameters, so set environment variables first:

Parameter (downloaded script)Environment variableWhat it does
-Version X.Y.ZOPTICS_VERSIONInstalls a specific release.
-Extra a,bOPTICS_EXTRAAlso installs engine extras.
-Dir PATHOPTICS_INSTALL_DIRInstalls somewhere other than ~\.optics.
-NoModifyPathOPTICS_NO_MODIFY_PATHLeaves your PATH alone.
-DryRunPrints what would happen and changes nothing.
-UninstallRemoves the managed install.

Install into a virtual environment you control. Add extras in the brackets.

See Install Optics for a step-by-step guide.
