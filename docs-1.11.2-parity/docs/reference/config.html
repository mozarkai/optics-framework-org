config.yaml

Every setting in a project's config.yaml.

View as Markdown

A project's config.yaml tells Optics which driver to use, how to find elements, and where to write logs and results. Every setting lives in the project; there's no global config file and no environment variable that overrides it.

Run optics configure to write a working file by answering a few questions, then edit it by hand with this page.

How Optics finds the file#

CommandWhich file it reads
optics execute, optics dry_runAny YAML file in the project tree that has driver_sources and elements_sources. The file name doesn't matter. If there are several, the last one found wins.
optics liveThe first YAML file in the project tree with any config key.
optics doctor, optics configure, optics generateExactly <folder>/config.yaml.
optics serve, optics mcpNone. Settings come from each session request.

We recommend one file named config.yaml at the project root, so every command reads the same settings.

Settings you leave out take their defaults. Optics ignores keys it doesn't know, so a typo such as log_levle is silently skipped.

Warning

If config.yaml has a wrong value type, optics execute logs the problem, skips the file and runs with defaults. The run then stops with "No driver enabled". Run optics doctor <folder> to find the problem.

Note

If you set execution_output_path yourself, create the folder first. JUnit results and logs create their own folders, but screenshots fail to save without a warning if the folder is missing.

Engine lists#

driver_sources, elements_sources, text_detection, image_detection and llm_models are lists. Each item is an engine name with its settings:

FieldDefaultWhat it does
enabledRequiredOnly enabled entries are loaded. A disabled entry with any name is ignored.
urlNoneThe server address, for engines that use one.
capabilities{}Settings passed to the engine.

When several entries in one list are enabled, Optics tries them in the order you list them. For element sources this is the order in which strategies run.

An enabled entry with an unknown name fails with E0601. So does an enabled engine whose extra isn't installed. A list you write replaces the default list completely.

driver_sources#

Enable one driver. optics live refuses more than one, and optics doctor warns about it.

NameExtraWhat it drives
appiumappiumAndroid, iOS, Android TV, Samsung Tizen TV and LG webOS TV apps through an Appium server.
seleniumseleniumChrome or Firefox through a Selenium server or Grid.
playwrightplaywrightChromium, Firefox or WebKit, on this computer or a remote browser. See Playwright capabilities.
blebleAny device paired with a Bluetooth mouse-and-keyboard dongle. For devices with no automation access.

elements_sources#

Enable the sources that match your driver. We recommend the locator, page source and screenshot sources for your driver. With Appium, add appium_web to find elements in web pages.

NameNeeds driverWhat it gives you
appium_find_elementappiumFinds elements by XPath, accessibility id and class.
appium_page_sourceappiumSearches the UI tree by XPath and text, with fuzzy matching. Lists interactive elements.
appium_screenshotappiumScreenshots for OCR, image matching and AI self-heal.
appium_webappiumFinds css= and DOM XPath locators in Chrome and WebViews on Android, and in Safari and WebViews on iOS. Lists the page's interactive elements. It does not tap an element that another element covers. See Test mobile websites.
selenium_find_elementseleniumFinds elements by XPath, text, id, name, CSS and link text.
selenium_page_sourceseleniumSearches the page HTML. Doesn't list interactive elements.
selenium_screenshotseleniumScreenshots for OCR and image matching.
playwright_find_elementplaywrightFinds elements by xpath=, css=, text=, label=, placeholder=, role=, id=, data-testid=, data-test= and data-test-id= locators. A value with no prefix is tried as text, label, placeholder, button name and link name.
playwright_page_sourceplaywrightSearches the page and lists interactive elements.
playwright_screenshotplaywrightScreenshots for OCR and image matching.
camera_screenshotAnyFrames from a webcam or a TCP frame server. Used with ble.

optics doctor fails a project when no enabled element source starts with the enabled driver's name.

llm_models#

Optics supports three LLM engines: gemini, openai and anthropic. Each has an extra of the same name, and the llm bundle installs all three. Use environment variables for keys, not config.yaml. If you enable more than one entry, Optics tries them in list order and moves to the next when a call fails.

Each engine also takes timeout_s under capabilities: the seconds that one request can take, default 60. A value that is not a positive number fails with E0601.

gemini#

SettingDefaultWhat it does
modelgemini-2.5-flashThe Gemini model.
use_vertexaiFrom GOOGLE_GENAI_USE_VERTEXAItrue uses Vertex AI instead of the Gemini API.
project, locationFrom GOOGLE_CLOUD_PROJECT, GOOGLE_CLOUD_LOCATIONThe Vertex AI project and region.
temperatureThe model's defaultSampling temperature.

Gemini reads its key from GEMINI_API_KEY or GOOGLE_API_KEY. For Vertex AI, set GOOGLE_GENAI_USE_VERTEXAI=true with GOOGLE_CLOUD_PROJECT, GOOGLE_CLOUD_LOCATION and GOOGLE_APPLICATION_CREDENTIALS. Optics accepts api_key or gemini_api_key in capabilities too, but warns when you use it.

nl_agent#

Settings for the plain-English mode of optics live. They apply only when an llm_models entry is enabled.

SettingDefaultWhat it does
visionautoWhen Optics sends a screenshot with the screen elements. auto sends one when the element list is not sufficient, for example after a failed step. always and never do what they say.
max_steps15The maximum number of steps for one instruction. It must be 1 or more.
escalation_model""A stronger model for difficult steps, such as a retry after a failure. It uses the engine of the first enabled llm_models entry. Empty uses the same model for all steps.

Examples by platform#

Before optics execute, Optics checks that the Appium server answers. If the server is on this computer, it also checks that adb devices lists a device.

optics doctor fails an iOS project without bundleId. The preflight checks only the Appium server.

Use Playwright unless you already run a Selenium Grid. It needs no server.

Open your site with a module step such as Launch App,https://birch.example.

Selenium won't start with empty capabilities or without browserName. The file optics configure writes for web-selenium has capabilities: {}, so add browserName before you run.

Appium capabilities#

Optics reads platformName, the app id and browserName. It passes every other capability to Appium unchanged. You can write any key with the appium: prefix, for example appium:udid.

platformNameApp id capabilityDefaults Optics adds (your values win)
AndroidappPackage and appActivitynoReset, newCommandTimeout: 3600, forceAppLaunch, shouldTerminateApp, ignoreHiddenApiPolicyError, settings: {waitForIdleTimeout: 1000} and a few others
iOSbundleIdThe same mobile defaults without ignoreHiddenApiPolicyError, and settings: {waitForIdleTimeout: 1}
TizenTVappPackagenewCommandTimeout: 3600, rcMode: remote, noReset: true
LGTVappIdnewCommandTimeout: 600, rcMode: rc, useSecureWebsocket: true, autoExtendDevMode: false, noReset: true

Any other platformName fails with E0104. To attach to an Appium session that's already running, add appium:existingSessionId. Optics starts a new session if it can't attach.

Idle wait. Before each action, Appium waits until the app is idle. waitForIdleTimeout sets the limit: 1000 ms on Android and 1 s on iOS. Optics merges your appium:settings with its defaults key by key. Set 0 to turn off the wait:

Web pages. These defaults let appium_web read web pages quickly:

platformNameDefaults
AndroidensureWebviewsHavePages: false, extractChromeAndroidPackageFromContextName: true
iOSincludeSafariInWebviews: true, additionalWebviewBundleIds: ["*"], webviewConnectRetries: 1, webviewAtomWaitTimeout: 5000

The iOS defaults apply only to app sessions. With browserName or autoWebview, the session starts in the browser and Optics leaves them out. See Test mobile websites.

Playwright capabilities#

Optics reads each key from capabilities or from the top level of the playwright entry. Web shows how to use them.

CapabilityDefaultWhat it does
browserchromiumchromium, firefox or webkit. optics setup downloads only Chromium.
headlessfalsetrue starts the browser without a window. A remote browser ignores it.
viewport{width: 1280, height: 800}The page size. It replaces the screen size of a device.
deviceNoneA Playwright device name, such as "iPhone 15". It sets the screen size, user agent and touch input. An unknown name fails with E0501. See Emulate a phone.
storage_stateNoneA browser state file that Playwright saved, relative to the project folder. The run starts with its cookies and storage. See Start signed in.
protocolcdpHow Optics connects to the browser in url: cdp (Chromium only) or playwright. See Use a remote browser.
headersNoneHTTP headers for the connection to a remote browser, as {name: value}.
contextnewexisting uses the remote browser's own context and open tab. You cannot use it with device or storage_state.
element_timeout_ms10000The wait for an element before an action.
navigation_timeout_ms60000The limit for a page load from Launch App or Go Back.
navigation_wait_untildomcontentloadedThe load event that a page load waits for: domcontentloaded, load, networkidle or commit.
settle_timeout_ms3000The wait for the page to stop changes before Optics reads it. 0 turns it off.
connect_timeout_ms90000The limit for the connection to a remote browser.
action_timeout_ms15000The limit for each other browser call, such as a key press or a screenshot.

Set url on the entry to connect to a remote browser instead of starting one. ${NAME} in url or in a headers value is read from the environment. If the variable is not set, the run stops with E0501. optics serve and optics mcp refuse ${NAME} and a storage_state file path.

TV#

Android TV uses the Android example. Samsung and LG TVs use Appium's TV drivers:

On Tizen and webOS, touch and typing keywords fail with E0105. Move around with Press Keycode and remote keys: UP, DOWN, LEFT, RIGHT, ENTER, BACK, HOME, PLAY, PAUSE, STOP, REWIND, FF. See Test TV apps.

BLE and camera#

The ble driver taps and types through a Bluetooth mouse-and-keyboard dongle. A camera or frame server provides the screen, and Optics finds elements with OCR or image templates.

ble capabilityDefaultWhat it does
device_idRequiredA name for the device.
portRequiredThe dongle's serial port (/dev/ttyACM0, COM3) or its USB product description.
pixel_width, pixel_height0The device screen size in pixels. Set them: taps can't be placed without them.
mickeys_width, mickeys_height0The device screen size in mouse movement units. Set them too.
x_invert, y_invert1-1 reverses the direction of mouse movement on that axis.
camera_screenshot capabilityDefaultWhat it does
camera_indexNoneThe webcam number. Use this or url.
urlNoneA TCP frame server as host:port.
header_size8Bytes in the frame server's length header: 4 or 8.
byte_orderlittleThe length header's byte order: little or big.

The BLE driver can't launch apps, so Launch App fails. Open the app by hand or with keys before the run. XPath and text locators don't work without a UI tree; use text that OCR can read, or image templates. See Test production devices.

include and exclude#

Run a subset of test cases. The --include and --exclude flags do the same for one run and replace these keys.

  • A name must match the full test_case name. Matching ignores case and extra spaces. * and ? are wildcards.
  • You can set both. Optics applies include first, then removes the exclude matches.
  • Each name must match a test case. A name that matches nothing stops the run before it starts, with a suggestion for the name.
  • Suite Setup, Suite Teardown and the per-test setup and teardown always run. See Setup and teardown.

Logging#

KeyDefaultWhat it does
log_levelINFOThe level for the console and the log files. Set DEBUG to see every strategy Optics tries.
file_logfalseWrites internal_logs.log and execution_logs.log to the output folder. Each rotates at 10 MB and keeps 10 old files.
log_pathNoneSends both logs to this one file.
json_logfalseWrites logs.json: a list of events with name, status, timings and log lines for each test case, module and keyword.
json_pathNoneWrites the JSON events here instead.
consoletrueNo effect.

With file_log: true and no execution_output_path, Optics also writes a copy of both logs to logs/ in the folder you ran optics from.

Optics masks secrets as **** in the console, the log files, the result tree and the Failure details:

  • Values you write with the @: prefix, such as @:s3cret.
  • Values that store_as or Read Data saves under a secret name. A name is secret if it contains one of these words: pass, password, passwd, passcode, pwd, pin, otp, secret, token, key or apikey. password1 and myAPIToken are secret names. Optics masks only values of 4 or more characters.

See Read results.

ai_self_heal#

When an element can't be found, self-heal sends a screenshot to an LLM and lets it try up to five corrective steps, such as scrolling or closing a popup.

  • It needs an enabled llm_models entry, that engine's extra and key, and a screenshot element source such as appium_screenshot. Without them it does nothing, and the run isn't affected.
  • It applies to keywords that find and act on an element: Press Element, Enter Text, Enter Number, Clear Element Text, Get Text, Swipe From Element, Scroll From Element, Detect And Press and Select Dropdown Option. It doesn't apply to assertions.
  • A healed step passes. Check the logs for AI self-heal: lines so a real regression doesn't go unnoticed.

optics serve and optics mcp ignore this key. They use per-session fields and the OPTICS_AI_SELF_HEAL variable instead. See Self-heal.

strict_element_match#

By default the page-source element sources (appium_page_source, selenium_page_source, playwright_page_source) accept close or partial text matches, so Sign in can match Sign in with email. Set strict_element_match: true to accept only exact matches. Turn it on when similar labels make tests press the wrong element.

save_captures#

When false, Optics does not write:

  • the files from Capture Screenshot, Capture Pagesource and Get Screen Elements,
  • the screenshot before each action, the detection screenshots and the area-of-interest screenshots,
  • failed_steps_elements.json.

Optics still writes the page source logs and the end-of-run screenshot. optics serve always turns captures off.

Starter config#

optics init writes a commented config.yaml with every engine disabled. To get started, enable one driver, enable its three element sources, and install the driver's extra with optics setup --install <name>. See Install Optics.
