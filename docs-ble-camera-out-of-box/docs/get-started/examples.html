Start from an example

Make a working suite for your platform with one command, then change it for your app.

Beginner, about 5 min

View as Markdown

Optics ships a sample suite for each platform. Each sample has a config.yaml for that platform and a short suite for an app that the platform has, where it has one. Copy one into a new project:

The project gets the files of the sample:

optics init demo with no --template shows a list of the samples in a terminal. optics quickstart offers the sample of the platform that you choose.

Choose an example#

SampleWhat the suite doesWhat you need
androidOpens Settings, scrolls to About phone and finds the build number. Includes an error definitions file.Appium, and an Android emulator or phone
iosOpens Settings, then General, then About, and goes back.Appium on a Mac with Xcode, and a simulator or iPhone
android_tvOpens TV Settings, then Device Preferences, and opens About with the remote's center key.Appium, and an Android TV emulator or a TV on adb
lg_tvOpens a tile in a grid with remote keys, then searches for it with the on-screen keyboard.Appium 2 with the webOS driver, and a TV in Developer Mode
samsung_tvThe same flow as lg_tv, on a Samsung Tizen TV.Appium 2 with the Tizen driver, Tizen Studio, and a TV in Developer Mode
browserOpens a page and checks its text.Nothing more: Playwright starts Chromium
browser_profileOpens GitHub settings with your Chrome profile, signed in.Chrome, signed in to GitHub
mobile_webSearches Wikipedia in Chrome on Android.Appium, and an Android emulator or phone
ble_cameraOpens Settings on an iPhone over Bluetooth, and reads the screen through a webcam.An airhand dongle and a webcam
ble_usbOpens Settings on an Android phone over Bluetooth, and reads the screen over USB.An airhand dongle, adb and USB debugging
mac_localTypes a note in TextEdit, checks it and clears it.Appium and appium-xa11y-driver on your Mac
mac_cloudAdds 7 and 8 in Calculator on a cloud Mac.A Mac Host with Appium and an SSH tunnel
windows_cloudAdds 7 and 8 in Calculator on a Windows VM.A Windows Host with Appium and an SSH tunnel

The TV samples drive Birch, the sample shoe store of these docs. Tizen and webOS drive only a debug build of your own app, so replace the app id and the text in elements.csv with the values of your app.

Phones and TVs#

android, ios and android_tv drive the Settings app, which every device has, so you can run them before you change anything. Before the first run, set the device in config.yaml:

SampleSet
android, android_tvdeviceName (or udid) to a serial from adb devices
iosdeviceName to a simulator name, or udid for a real iPhone
lg_tvappium:deviceHost to the TV's address, and appium:appId to your app
samsung_tvappium:deviceAddress, appium:rcToken, appium:appPackage and appium:app (the .wgt file)

Android TV moves the focus with Android key numbers, such as 23 for the center key. Tizen and webOS take remote key names, such as RIGHT and ENTER, and Press Element moves the focus for you. Test TV apps explains both.

Browsers#

browser runs as it is. browser_profile copies the sign-ins of a Chrome profile into a temporary folder, so the suite starts signed in, and your profile does not change. Set the profile with an environment variable, or edit config.yaml:

The value is the profile folder, its name or its account email. Start signed in with a browser profile has the details.

Devices over Bluetooth#

The ble samples drive a device that has nothing installed. The dongle taps and types, and Optics reads the screen with OCR. The two samples see the screen in different ways:

SampleScreenKeep in step
ble_cameraA webcam aimed at the phone, with find_screen: brightnessframe equals out_width × out_height
ble_usbadb screenshots over USBframe equals the size of the phone's screenshot

Each step that taps waits first with Assert Presence, because a camera frame shows the screen only at one moment. Test production devices covers the camera, the dongle and the setup.

Desktops#

mac_local drives TextEdit on the Mac that runs Optics. The cloud samples drive a Host on another computer through an SSH tunnel, because Appium has no authentication:

The URL comes from MAC_APPIUM_URL or WINDOWS_APPIUM_URL, with the tunnel port as the default. Test desktop apps shows how to set up a Host.

Make it yours#

  1. 1

    Check the setup#

    optics doctor checks the driver, the server and the device for the project:

  2. 2

    Run the sample once#

    Run it before you change anything. Then a failure after your change comes from your change.

  3. 3

    Point it at your app#

    Change the app in config.yaml, and the locators in test_data/elements.csv. Keep the module and test case names, or rename them to match your flow.

  4. 4

    Check your changes without a device#

    A dry run finds a misspelled keyword, a missing ${name} or a wrong number of values before anything runs:
